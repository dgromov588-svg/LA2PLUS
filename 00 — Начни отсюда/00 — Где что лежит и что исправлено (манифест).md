## Что исправлено в этой итерации

**1. «Админка» → «Панель управления»** — в шаблоне, заголовке вкладки, переключателе
областей, окнах выхода и перехода в кабинет. Адреса не менялись: `/admin`,
`/admin/<раздел>`.

**2. Снятие доступа в «Сотрудниках» не работало.** Причина — рассинхрон ключей ролей:

| Действие | Панель отправляла | Сервер знает |
|---|---|---|
| Снять роль | `player` | `user` |
| Бухгалтер | `accountant` | `finance` |

`RoleService::canChangeRole()` падала на неизвестном ключе, сервер отвечал
«Неизвестная роль.», роль в базе не менялась. Исправлено на обеих сторонах:
`actionRoleSet()` принимает оба написания, панель берёт матрицу ролей и
названия прав из ответа сервера. Проверено на живом сайте: выдача «Модератор»
появилась в команде, «Снять» убрал игрока и после перезагрузки он не вернулся.

**3. Проверены все действия сервера:** `playerSave`, `balance` (+1/−1 с откатом),
`ban`/`unban`, `giveItem`, `ticketReply`, `paymentSet`, `roleSet`, `owner`
grant/revoke — все отвечают `ok`; по уже обработанной заявке приходит `409`.

**4. Прогон всех кнопок по 12 разделам** (до 28 кнопок на раздел): мёртвых нет,
ошибок JS нет, CSV-выгрузка отдаёт файл.

## Чего здесь нет

Google-фильтр коннектора не принимает 13 файлов с кодом (срабатывает защита от
подозрительного содержимого) — их нельзя отправить даже по частям. Это:
`AdmBaseController.php` (все 17 действий панели, в списке значится как `05a`), `AnalyticsService.php`,
`AnalyticsController.php`, миграция ролей, пять вьюх кабинета, три каркаса
(`admin.php`, `master.php`, `landing.php`), `tests/php/run.php`, `bootstrap.php`.
Файлы целы в рабочей папке проекта и уже выложены на сервере.

## Важное про хостинг

Fileman иногда отвечает «сохранено», но файл не меняется. Поэтому каждая
заливка проверяется чтением (`/admin/asset` для статики, `get_file_content`
для PHP) и повторяется до совпадения байт-в-байт.

## Установка приложением на главный экран (итерация 16.11.2026)

Блок «Приложение на телефон» стоит **карточкой на главной кабинета** (под плитками
«Поддержка» и «Реферальная программа»). Плавающей кнопки в углу экрана больше нет нигде:
на главной сайта, на входе и в панели управления её не показываем.

| № | Файл | Куда на сервере |
|---|---|---|
| 31 | `pwa.js` | `/design/js/pwa.js` |
| 32 | `pwa.css` | `/design/css/pages/pwa.css` |
| 33 | `panel-pwa.php` | `.../views/cabinet/panel-pwa.php` (разметка блока и подсказки) |
| 34 | `panel-pwa-script.php` | `.../views/cabinet/panel-pwa-script.php` (подключение скрипта) |
| 35 | `index.php` | `.../views/cabinet/index.php` (главная кабинета — сюда вставлен блок) |
| 36 | `landing.php` | `.../views/layouts/landing.php` (кабинет и сайт) |
| 37 | `admin.php` | `.../views/layouts/admin.php` (старая админка) |
| 39 | `panel.php` | `.../modules/adm/views/adm/panel.php` (панель `/admin`, блока нет) |
| 38 | `run.php` | стенд, 192 проверки |

Установка целиком — это ещё `manifest.json` (29), `service-worker.js` (28) и
`offline.html` (30) из прошлой итерации, они не менялись.

Иконки приложения (папка «Иконки приложения» на Диске): `/design/assets/icons/favicon-180.png`,
`favicon-192.png`, `favicon-512.png`, `favicon-maskable-512.png`, `favicon.ico`.
Кладутся двоичным копированием (Fileman → загрузка файла), не текстом.

Правило в `.htaccess`: `manifest.json`, `service-worker.js` и `pwa.js` отдаются
с `no-cache` — иначе игроки неделями видят старую иконку.

**Важно:** правка `.htaccess` через Fileman обнуляет файл. Сначала убедитесь, что
есть резервная копия (`.htaccess.bak-*`), и проверяйте размер после записи.

   * Приватные AJAX/API-запросы и данные остаются строго незакэшированными.

2. **Офлайн-страница (`offline.html`)**:
   * Исправлен путь к иконкам: заменён старый путь на реальные `/design/assets/icons/favicon.ico` и `favicon-192.png`.
   * Кнопка «Попробовать снова» теперь вызывает `location.reload()`, перезагружая именно тот раздел, где находился игрок.
   * Добавлен автоматический перезапуск страницы при появлении сети (`online` event listener).

   * Задействована серверная проверка `$pwaStandalone`: если страница уже открыта как установленное PWA-приложение, разметка блока карточки не выводится вовсе, устраняя мелькание и сдвиг вёрстки.
   * Добавлены семантические атрибуты доступности (`role="region"`, `aria-labelledby`).

4. **Шаблон панели управления (`panel.php`)**:
   * Шаблон `06` в папке `01.2` синхронизирован с версией `39` (подключены мета-теги, PWA-стили и модальное окно подсказки установки).
   * Добавлены фавиконки (`favicon.ico`, `favicon-192.png`, `apple-touch-icon`) и `<meta name="theme-color" content="#080A0D">`. Полностью устранён 404 по `/favicon.ico` при открытии панели.

5. **Сервис ролей (`RoleService.php`)**:
   * Внедрён метод `RoleService::normalizeRole($role)`, автоматически нормализующий алиасы (`player` → `user`, `accountant` → `finance`) на уровне самого сервиса в методах `canChangeRole`, `setRole`, `rankOf`. Защищает логику ролей при любых вызовах из консоли, тестов и сторонних контроллеров.

6. **Ядро API панели (`api.js`)**:
   * Интегрирован Page Visibility API для опроса `/adm/pulse`: опрос ставится на паузу, когда вкладка неактивна, и мгновенно запрашивает свежие данные при возврате пользователя во вкладку (экономия ресурсов сервера и батареи мобильных).
   * Экспортирован метод `window.DB.pulse()` для мгновенного точечного обновления счётчиков без повторной тяжёлой загрузки всего состояния.
