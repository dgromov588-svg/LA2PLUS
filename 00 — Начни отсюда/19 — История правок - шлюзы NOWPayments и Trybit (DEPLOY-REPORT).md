## Таблицы на телефоне

Причина обрезки: у `.card--flat table.t` стоял `min-width:560px`. На 390px
таблица вылезала за край, и правые колонки были не видны.

* новые правила `.t--cards`: строка таблицы становится карточкой, перед
  каждым значением — подпись колонки (ВРЕМЯ, КТО, ДЕЙСТВИЕ, …);
* `display:block` для `table/tbody` — без него таблица сохраняла ширину
  содержимого (603px) даже при `width:100%`;
* `min-width:0 !important` перекрывает общее правило 560px;
* матрица прав («Роль» + роли в столбцах) не ломается — у неё остаётся
  горизонтальная прокрутка;
* список игроков на ≤860px рисуется своим компактным видом: логин и баланс
  в первой строке, id и e-mail во второй, персонажи/вход/статус в третьей.

Заголовок «Игроки сайта» больше не пишет «Всего 2 аккаунтов» при включённом
фильтре: теперь «Всего 174 … · в фильтре 2».

## Заливка файлов

У Fileman нашлась неприятная особенность: `upload_files` и
`save_file_content` иногда отвечают успехом, а файл остаётся прежним.

`X-Asset-Bytes` / `X-Asset-Mtime` показывают, какая версия реально ушла
в браузер.

## Как приходят деньги

1. Игрок выбирает способ в магазине → создаётся заявка `transactions`
   (`status = 0`) → редирект на страницу шлюза.
2. Оплата → шлюз шлёт уведомление:
   * NOWPayments → `POST /deposit-nowpayments.php`, подпись `x-nowpayments-sig`
     (HMAC-SHA512, ключи сортируются по алфавиту);
   * Trybit → `POST /deposit-trybit.php`, подпись JWT HS256 на `secret_key`.
3. Телу запроса не верим: `syncPayment()` перезапрашивает состояние платежа
   у API и сверяет **владельца** (`order_id` = номер заявки) и **сумму**.
4. `DepositCreditService::creditDepositTransaction()` начисляет монеты на
   баланс (+ партнёрский процент) — идемпотентно.
5. Если уведомление потерялось: страница пополнения досверяет последние
   5 заявок за сутки, а `deposit-cron.php` — все висящие (раз в 5 минут).
