# new.la2plus.com — отдельная тестовая площадка

Опубликовано 18 ноября 2026 года на существующем cPanel-хостинге. Это отдельное PHP-приложение, основной сайт не заменён.

- URL: https://new.la2plus.com/; вход в форме кабинета. HTTP Basic Auth удалена.
- Document root: `/home/laplusco/new.la2plus.com`.
- PHP: отдельный обработчик `application/x-httpd-alt-php83___lsphp`, проверен PHP 8.3.36.
- Базы: `laplusco_newcms` и `laplusco_newgame`; отдельный пользователь имеет доступ только к ним. Игровые подключения дополнительно проверяются при каждом запросе.
- Созданы вымышленные профили PreviewOwner и PreviewUser, персонажи, каталог вещей и демонстрационные лоты. Реальные аккаунты, транзакции, обращения игроков и игровые предметы не копировались.
- Пароли, PIN и ключи отсутствуют в Git. В рабочей среде инструкции владельцу: `work/staging/ACCESS.txt`. Файл `credentials.json` предназначен только для закрытой рабочей среды, публиковать его нельзя.

## Поведение демонстрации

`StagingGameAdapter` работает только при одновременном выполнении условий: константа тестового запуска, параметр staging, точный hostname, точная отдельная CMS-база и флаг `staging_demo_inventory=1`. Он проверяет привязку персонажа, переносит предметы в отдельном демонстрационном инвентаре и хранит квитанции повторных операций в транзакциях InnoDB. Аугментация, заточка и дополнительные атрибуты сохраняются.

Включены внутренние демонстрационные торговля, склад, перевод CoL и заявки вывода. На странице кошелька есть **«Демонстрационное пополнение»**: оно добавляет виртуальные деньги без обращения к платёжному провайдеру, с защитой от повторного зачисления. Заявки вывода не выполняют реальный перевод криптовалюты.

Боевые флаги `bridge_verified`, `topup_enabled`, `net_topup_verified` остаются 0. `StagingConfig` принудительно отключает ключи/настройки платёжных систем и SMTP даже при изменении их через админку. Прямые обработчики старых оплат также заблокированы. Демо-настройка CoL ID 4037 используется только в вымышленном инвентаре: это не утверждение о настоящем ID CoL проекта.

Письма перехватываются локально. `/test-mail/` доступен только после входа тестовым владельцем. Обычный игрок получает 403. Коды действуют ограниченное время, одноразовые, привязаны к почте; они не возвращаются в JSON API.

## Конфигурация развёртывания

- `index.php`: входной файл тестового домена; отдельная папка PHP-сессий, имя cookie, режим запуска и приватный журнал ошибок.
- `main.php`: обёртка над `main-base.php` — исходной конфигурацией CMS в **тестовой** папке. Настраивает отдельную БД, подпись cookie, пространства состояний, владельца тестовых данных и обработчики защиты. `staging.json` содержит случайные ключи; `database.php` содержит только реквизиты тестового пользователя БД.
- `StagingGuard.php`, `StagingConfig.php`, `StagingGameAdapter.php`: устанавливаются в `cms-private/protected/components/` только тестовой копии. Notify в тестовой копии перехватывает отправку через `StagingGuard::capture`.
- `LoginController.php`: устанавливается как `protected/modules/login/controllers/DefaultController.php` только тестовой копии. Использует стандартную проверку пароля и ограничение попыток CMS, меняет представление на новый экран входа.
- `public.htaccess`: правила корня тестового домена; HTTPS, запрет индексации, доступа к private/config/log/backup-файлам и исполнения PHP, кроме входного файла. Правила основного сайта не изменяются.

PWA на тестовом домене использует network-only service worker: авторизованные страницы, формы и почтовые коды не кешируются. Кеши и cookies основного домена не используются.

Временные скрипты установки и проверки PHP удалены. CGI/служебные пути не являются интерфейсом настройки площадки. Миграции выполнять только закрытым администраторским процессом с проверкой целевого домена и баз; обход авторизации кабинета для установки не использовать.

## Проверки

- 75 проверок бизнес-логики, отдельные проверки конкурирующих покупателей и рейтингов.
- 12 проверок изоляции демо-режима и принудительного отключения внешних сервисов.
- 53 сквозные проверки тестовой площадки: вход/выход, виртуальное пополнение с повтором, торговля, перенос аугментированного +16 предмета, перевод CoL, заявки вывода, почтовые коды и семь вкладок рейтинга.
- 38 проверок готовности: неверный пароль, восстановление входа по подписанной cookie, старые страницы кабинета, CSRF, 21 экран на ширинах 390/768/1440, уменьшенная анимация, выбор инвентаря и ограничения доступа игрока.
- На отдельной проверке подтверждены атрибуты `variationId1=123`/`variationId2=456` после переноса предмета.

Сквозной тест: `node implementation/tests/staging-e2e.cjs`. Использует только этот тестовый hostname и реквизиты из закрытой рабочей папки. Тест меняет виртуальные данные, поэтому предназначен для тестового стенда. Данные тестового инвентаря и демо-лоты после проверки дополнены для просмотра владельцем.

## Переход к боевому запуску

Эта папка — конфигурация демонстрации. Не переносить её, тестовые базы, реквизиты или демо-флаги в production. Для настоящих предметов нужен проверенный серверный адаптер по `GAME-BRIDGE.md`; для реальных оплат — отдельная настройка и проверка провайдера. Карты, Apple Pay и Google Pay здесь не подключены.
